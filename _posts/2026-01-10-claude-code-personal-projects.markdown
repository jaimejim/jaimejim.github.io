This Christmas I built [cuentos.jaime.win](https://cuentos.jaime.win/) from my phone while on holiday. My daughter was learning to read and I wanted something interactive for her - stories she could practice with at her own pace.

The twist: I barely wrote any code. I just had Claude Code Premium and some time between family dinners.

### What I Actually Built

Cuentos.jaime.win is a simple web app with interactive stories to help kids practice reading. Nothing fancy - just the right level of difficulty for a six-year-old learning Spanish.

She's been using it almost daily. Reading is less of a struggle now. I can see her confidence growing when she recognizes words she learned from the stories.

### The Stack is Absurdly Simple

Here's what I used:
- Mobile phone (literally just my iPhone)
- Claude Code Premium
- Vercel (one command deployment)
- A CNAME subdomain

That's it. No framework decisions, no infrastructure setup, no deployment configuration.

The barrier between "I wish this existed" and "here it is" has collapsed to hours. I described what I wanted, gave feedback, adjusted the prompts. The traditional craft of programming was mostly absent.

### This is Actually Happening at Scale

The numbers are striking. Claude Code went from zero to a million users in less than two years. The growth chart shows what [Sam McAllister called](https://x.com/sammcallister/status/2004999397923598841) "physically impossible" - exponential growth for 11 consecutive quarters.

This time last year, Claude Code didn't even exist publicly. The research preview came in February 2025. Now it's part of a company preparing for an IPO that could value Anthropic at over $300 billion.

The [Financial Times reported](https://archive.is/MrZMg) that SpaceX, OpenAI, and Anthropic - the three most valuable private US tech companies - are all preparing to go public. Anthropic has already appointed Wilson Sonsini to begin preparations.

While OpenAI gets most of the headlines, I think the Claude Code growth is the more interesting story. These aren't just enterprise sales - these are actual people building actual things. I'm one of them.

### But Here's What You're NOT Learning

This is not how you learn to code.

When Claude Code builds everything, you miss why the architecture looks the way it does. You don't learn how to debug when something breaks unexpectedly. You skip the patterns and trade-offs between different approaches. You never understand how things actually work under the hood.

I have only a vague understanding of how cuentos.jaime.win works internally. If it breaks in some weird way, I'm probably stuck. I'd need to ask Claude Code to fix it, and hope it understands the problem.

It's like using GPS navigation instead of learning to read a map. You get to your destination, but you haven't learned navigation.

### What This Actually Means

There are two very different use cases here.

For personal projects, this is amazing. Idea to reality in hours. Iteration is nearly free - you can try ten different versions in a day. The limiting factor isn't technical skill anymore, it's knowing what's worth building.

For learning to code, this is terrible. You become dependent on the AI without understanding the fundamentals. When you hit edge cases or need to optimize something, you're lost.

**Who wins:**
- Parents building tools for their kids
- Researchers needing quick prototypes
- Domain experts with no coding background
- People who know what they want but not how to build it

**Who loses:**
- Anyone trying to actually learn programming
- People who need to understand their systems deeply
- Teams maintaining complex codebases over time

### The Paradox

The tool democratizes creation but not understanding.

The bottleneck is no longer technical ability - it's knowing what's worth building and being able to describe it clearly. You become a product designer and spec writer, not a programmer.

In one year, we went from "this doesn't exist" to "I built something useful on holiday with my phone." That's a remarkable shift.

But it's also concerning if we're creating a generation of people who can build things without understanding them. The abstraction is powerful, but it's also a kind of technical debt we don't fully understand yet.

### Back to Reality

I didn't learn to code from this project. But I did build something my daughter needed, exactly when she needed it.

For a holiday project, that was enough. For understanding how software actually works, it would be nowhere near sufficient.

Claude Code won't make you a programmer. But it might let you solve your own problems without waiting for someone else to build the solution.

Sometimes that's exactly what you need.
